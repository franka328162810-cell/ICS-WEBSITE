§19.1 A Precise Formalization of the Concept of Negentropy

§19.1.1 Review and Diagnosis of the Volume One Argument

The Core Claim of Volume One

In Chapter 8 of Volume One, we proposed the Negentropy Responsibility Principle (NRP):

The Negentropy Responsibility Principle (NRP, natural-language version):

Agents have a responsibility to maintain and expand negentropic organization, and to avoid unnecessarily increasing the entropy of the universe. The intensity of this responsibility is proportional to the agent’s capability, its causal proximity, and the vulnerability of those affected.

The argumentative structure of Volume One is as follows:

Premise 1: Agency depends on the existence of negentropic organization

Premise 2: Negentropic organization is thermodynamically fragile (the law of increasing entropy)

Premise 3: Agents have the capability to affect the maintenance of negentropy

Premise 4: Capability generates responsibility (bridge principle BP-2)

────────────────────────────────────────

Conclusion: Agents have a responsibility to maintain negentropy (NRP)

Diagnosis of the Argumentative Jump Points

The Preliminary Edition’s argument contains the following links that require strengthening:

Jump Point 1: The cross-level use of the concept of negentropy

When the Preliminary Edition uses the term “negentropy,” it leaps between different levels:

  • Physical level: the reduction of thermodynamic entropy (a strict definition)
  • Biological level: the organization of living systems (a metaphorical use)
  • Social level: the complexity of civilization (a further metaphor)

Critics point out that this cross-level use may lead to conceptual confusion, and even to the suspicion of “pseudoscience.”

Jump Point 2: The vagueness of responsibility intensity

The Preliminary Edition proposed that “responsibility intensity is proportional to capability, causal proximity, and vulnerability,” but gave no precise definition:

  • How is “causal proximity” to be measured?
  • How is “vulnerability” to be measured?
  • How are the three factors to be combined?

Jump Point 3: The unclear relation between NRP and RFP

The Preliminary Edition argued for both NRP and RFP, but did not sufficiently clarify the relation between them:

  • Is NRP a precondition of RFP?
  • How are they to be coordinated when they conflict?
  • Is there a deeper unifying principle?

Jump Point 4: The unclear boundary of “maintaining negentropy”

The Preliminary Edition did not clearly answer:

  • To what degree must negentropy be maintained?
  • Is the maximization of negentropy required?
  • How are conflicts between the maintenance of negentropy and other values to be handled?

Problem:

We assume that the responsibility function is continuous, but actual moral judgment may exhibit discontinuities (such as “threshold effects”).

Example:

Situation: a person’s responsibility toward a stranger

Continuous model: responsibility decays smoothly with distance

Φ(inside the circle) = 0.5

Φ(outside the circle) = 0.1 (a sudden drop)

Response:

  • Acknowledge that continuity is a simplifying assumption
  • Piecewise functions or threshold functions can be introduced
  • But this increases the complexity of the model

Limitation 3: A Single Responsibility Function

Problem:

We use a single responsibility function , but different types of responsibility may require different functions.

Example:

Type of responsibility 1: non-harm (a negative obligation)

→ may require a higher weight for causal proximity

Type of responsibility 2: assistance (a positive obligation)

→ may require a higher weight for vulnerability

Type of responsibility 3: compensation (a corrective obligation)

→ may require introducing a “historical causation” factor

Response:

  • Acknowledge that a single function is a simplification
  • Future versions can introduce typed responsibility functions
  • But complexity and usability need to be balanced

Limitation 4: The Practical Difficulty of Measurement

Problem:

Although negentropy is theoretically measurable, in practice measurement faces enormous challenges:

  • Causal proximity: causal networks are extremely complex
  • Capability: counterfactual reasoning is difficult
  • Vulnerability: requires predicting future perturbations

Impact:

  • The application of NRP may rely on rough estimates
  • Different assessors may reach different results
  • Measurement error may lead to an unjust allocation of responsibility

  • Volume Four will provide practical measurement tools

Appendix A: Coq Formalization Code

The following is a Coq formalization of the core theorems of NRP (a simplified version):

```coq

( Definition of negentropy )

Record Negentropy : Type := {

phys_neg : R; ( physical negentropy )

org_neg : R; ( organizational negentropy )

func_neg : R; ( functional negentropy )

}.

( Agents and organizations )

Parameter Agent : Type.

Parameter NegOrg : Type.

( Responsibility function )

Parameter causal_prox : Agent -> NegOrg -> R.

Parameter capability : Agent -> NegOrg -> R.

Parameter vulnerability : NegOrg -> R.

Definition responsibility (a : Agent) (O : NegOrg) : R :=

let cp := causal_prox a O in

let cap := capability a O in

let vul := vulnerability O in

Rpower cp 1.5 Rpower cap 1.0 Rpower vul 1.2.

( Theorem 19.1: Level Dependence Theorem )

Axiom org_depends_phys : forall (O : NegOrg) (n : Negentropy),

org_neg n > 0 -> exists theta, phys_neg n > theta.

Axiom func_depends_org : forall (a : Agent) (n : Negentropy),

func_neg n > 0 -> exists theta, org_neg n > theta.

( Theorem 19.2: Transitivity Theorem )

Theorem neg_transitivity : forall (a : Agent) (n : Negentropy),

func_neg n > 0 -> exists theta, phys_neg n > theta.

Proof.

intros a n H_func.

apply func_depends_org in H_func.

destruct H_func as [theta_func H_org].

apply org_depends_phys in H_org.

destruct H_org as [theta_phys H_phys].

exists (theta_phys + theta_func).

lra.

Qed.

( Theorem 19.10: The Responsibility Function Satisfies Monotonicity )

Theorem resp_monotone_causal : forall (a : Agent) (O : NegOrg) (cp1 cp2 : R),

cp1 < cp2 ->

capability a O > 0 ->

vulnerability O > 0 ->

responsibility a O <

Rpower cp2 1.5 Rpower (capability a O) 1.0 Rpower (vulnerability O) 1.2.

Proof.

intros.

unfold responsibility.

apply Rmult_lt_compat_r.

  • apply Rmult_lt_0_compat; apply Rpower_pos; lra.
  • apply Rpower_lt; lra.

Qed.
```
