§2.1 Logical Foundations

§2.1.1 First-Order Logic

Why do we need first-order logic?

First-order logic is the standard tool for formalization in mathematics and philosophy. It provides:

  • Quantifiers (∀, ∃): expressing "all" and "there exists"
  • Predicates: expressing properties and relations of objects
  • Functions: expressing mappings between objects

Syntax:

Basic symbols:

  • Variables: x, y, z, ...
  • Constants: a, b, c, ...
  • Function symbols: f, g, h, ...
  • Predicate symbols: P, Q, R, ...
  • Logical connectives: ∧, ∨, →, ↔, ¬
  • Quantifiers: ∀, ∃
  • Equality: =

Terms:

```

t ::= x | c | f(t₁, ..., tₙ)

```

Formulas:

```

φ ::= P(t₁, ..., tₙ) | t₁ = t₂ | ¬φ | φ ∧ ψ | φ ∨ ψ | φ → ψ | ∀x φ | ∃x φ

```

Semantics:

Structure:

M = (D, I)

  • D: the domain (a non-empty set)
  • I: the interpretation function
  • I(c) ∈ D (interpretation of constants)
  • I(f): Dⁿ → D (interpretation of functions)
  • I(P) ⊆ Dⁿ (interpretation of predicates)

Satisfaction:

  • M ⊨ P(t₁, ..., tₙ) iff (I(t₁), ..., I(tₙ)) ∈ I(P)
  • M ⊨ ¬φ iff M ⊭ φ
  • M ⊨ φ ∧ ψ iff M ⊨ φ and M ⊨ ψ
  • M ⊨ ∀x φ iff for all d ∈ D, M[x:=d] ⊨ φ

Inference rules:

Natural deduction system:

[Introduction rules]

∧-Intro: φ ψ ----- φ ∧ ψ

∀-Intro: φ[x] (x does not occur free in the assumptions) ----- ∀x φ

[Elimination rules]

∧-Elim: φ ∧ ψ φ ∧ ψ ----- ----- φ ψ

∀-Elim: ∀x φ ----- φ[t/x]

Important meta-theorems:

Theorem 2.1 (Soundness): If ⊢ φ, then ⊨ φ

Theorem 2.2 (Completeness, Gödel): If ⊨ φ, then ⊢ φ

Theorem 2.3 (Compactness): If every finite subset of Γ is satisfiable, then Γ is satisfiable

Applications in this book:

  • The basic structure of ontology (Chapters 4-6)
  • The basic relations of epistemology (Chapters 7-9)
  • The basic formulation of normativity (Chapters 10-12)

First-order logic in Coq:

```coq

( universal quantification )

Theorem forall_example : forall (A : Type) (P : A -> Prop),

(forall x, P x) -> forall y, P y.

Proof.

intros A P H y.

apply H.

Qed.

( existential quantification )

Theorem exists_example : forall (A : Type) (P : A -> Prop) (x : A),

P x -> exists y, P y.

Proof.

intros A P x H.

exists x.

exact H.

Qed.

```

§2.1.2 Modal Logic

Why do we need modal logic?

Modal logic extends first-order logic by adding:

  • The necessity operator (□): expressing "necessarily"
  • The possibility operator (◇): expressing "possibly"

This is crucial for formulating normativity.

Syntax:

On the basis of first-order logic, add:

φ ::= ... | □φ | ◇φ

Semantics: possible-world semantics (Kripke semantics)

Frame:

F = (W, R)

  • W: the set of possible worlds
  • R ⊆ W × W: the accessibility relation

Model:

M = (W, R, V)

  • V: the valuation function, V(p, w) ∈ {true, false}

Satisfaction:

  • M, w ⊨ □φ iff for all w' such that wRw', M, w' ⊨ φ
  • M, w ⊨ ◇φ iff there exists w' such that wRw' and M, w' ⊨ φ

Modal logic systems:

System K (the weakest):

K axiom: □(φ → ψ) → (□φ → □ψ)

Necessitation rule: If ⊢ φ, then ⊢ □φ

System T:

K + T axiom: □φ → φ

Correspondence: R is reflexive

System S4:

T + 4 axiom: □φ → □□φ

Correspondence: R is reflexive and transitive

System S5 (the strongest):

S4 + 5 axiom: ◇φ → □◇φ

Correspondence: R is an equivalence relation

Our choice: S5

Reasons:

  • S5 is suited to formulating the modal structure of normativity
  • All possible worlds in S5 are mutually accessible
  • S5 has a concise semantics and a complete proof system

Applications in this book:

  • The modal structure of normative principles (Chapter 10)
  • The formalization of the space of possibilities (Chapter 23)

Modal logic in Coq:

```coq

( definition of possible worlds )

Parameter World : Type.

Parameter R : World -> World -> Prop.

( necessity )

Definition Box (P : World -> Prop) (w : World) : Prop :=

forall w', R w w' -> P w'.

( possibility )

Definition Diamond (P : World -> Prop) (w : World) : Prop :=

exists w', R w w' /\ P w'.

( equivalence-relation properties of S5 )

Axiom R_reflexive : forall w, R w w.

Axiom R_symmetric : forall w w', R w w' -> R w' w.

Axiom R_transitive : forall w w' w'', R w w' -> R w' w'' -> R w w''.

```

§2.1.3 Deontic Logic

Why do we need deontic logic?

Deontic logic specifically studies normative concepts such as obligation, permission, and prohibition.

Basic operators:

  • O(φ): it is obligatory to do φ
  • P(φ): it is permitted to do φ
  • F(φ): it is forbidden to do φ

Relations:

P(φ) ≝ ¬O(¬φ) (permission = no obligation not to do)

F(φ) ≝ O(¬φ) (prohibition = obligation not to do)

Standard Deontic Logic (SDL):

Axioms:

D1: O(φ → ψ) → (O(φ) → O(ψ)) [deontic version of the K axiom]

D2: ¬O(⊥) [consistency of obligation]

D3: O(φ) → P(φ) [obligation implies permission]

Inference rules:

RE (rule of equivalence): If ⊢ φ ↔ ψ, then ⊢ O(φ) ↔ O(ψ)

RN (rule of necessitation): If ⊢ φ, then ⊢ O(φ)

Possible-world semantics:

Deontic model:

M = (W, R_O, V)

  • W: possible worlds
  • R_O: the deontic accessibility relation (w R_O w' means w' is a deontically ideal world of w)
  • V: the valuation function

Satisfaction:

M, w ⊨ O(φ) iff for all w' such that w R_O w', M, w' ⊨ φ

Problems with SDL:

Problem 1: the Contrary-to-Duty Paradox

Consider:

1. O(help the neighbor)

2. If you do not help the neighbor, then O(apologize)

3. You do not help the neighbor

SDL derives a contradiction.

Problem 2: the Good Samaritan Paradox

From "it is obligatory to help the person who has been robbed", SDL derives "it is obligatory that there exists a person who has been robbed".

Solution:

We use an extended version of SDL, adding:

  • Conditional obligation: O(φ|ψ) (φ is obligatory under the condition ψ)
  • Priority relations: to handle conflicts of obligation

Applications in this book:

  • The formalization of the Three Normative Principles (Chapter 10)
  • The derivation of the taboo red lines (Chapter 10)
  • The formalization of normative decision-making (Chapter 20)

Deontic logic in Coq:

```coq

Notation "'O' p" := (Obligation p) (at level 75).

Parameter Permission : Prop -> Prop.

Notation "'P' p" := (Permission p) (at level 75).

§2.1.4 Temporal Logic

Why do we need temporal logic?

Temporal logic is used to express temporal relations and processes, which is relevant to:

  • The formalization of process ontology
  • The formulation of intergenerational decision-making
  • The temporal dimension of reversibility

Basic operators:

Linear Temporal Logic (LTL):

  • G(φ): always φ (Globally)
  • F(φ): eventually φ (Finally)
  • X(φ): φ at the next moment (neXt)
  • φ U ψ: φ until ψ (Until)

Relations:

F(φ) ≝ true U φ

G(φ) ≝ ¬F(¬φ)

Semantics:

Temporal structure:

T = (N, <) (the less-than relation on the natural numbers)

Path:

π = s₀, s₁, s₂, ... (a sequence of states)

Satisfaction:

```

π, i ⊨ X(φ) iff π, i+1 ⊨ φ

π, i ⊨ F(φ) iff exists j ≥ i such that π, j ⊨ φ

π, i ⊨ G(φ) iff for all j ≥ i, π, j ⊨ φ

π, i ⊨ φ U ψ iff exists j ≥ i such that π, j ⊨ ψ and

for all i ≤ k < j, π, k ⊨ φ

```

Important properties:

G(φ → ψ) → (G(φ) → G(ψ)) [distribution law]

G(φ) → φ ∧ X(G(φ)) [unfolding law]

F(φ) ↔ φ ∨ X(F(φ)) [unfolding law]

Applications in this book:

  • The formalization of process ontology (Chapter 5)
  • The temporal structure of intergenerational decision-making (Chapter 18)
  • The temporal dimension of reversibility (Chapter 23)

Temporal logic in Coq:

```coq

( time points )

Definition Time := nat.

( states )

Parameter State : Type.

Parameter path : Time -> State.

( temporal operators )

Definition Next (P : State -> Prop) (t : Time) : Prop :=

P (path (S t)).

Definition Eventually (P : State -> Prop) (t : Time) : Prop :=

exists t' : Time, t' >= t /\ P (path t').

Definition Always (P : State -> Prop) (t : Time) : Prop :=

forall t' : Time, t' >= t -> P (path t').

Definition Until (P Q : State -> Prop) (t : Time) : Prop :=

exists t' : Time, t' >= t /\ Q (path t') /\

forall t'' : Time, t <= t'' < t' -> P (path t'').

```

§2.1.5 Epistemic Logic

Why do we need epistemic logic?

Epistemic logic is used to express knowledge and belief, which is relevant to:

  • The formalization of the New View of Cognition
  • The formulation of the sociality of knowledge
  • Multi-agent decision-making

Basic operators:

Single agent:

  • K_i(φ): agent i knows φ
  • B_i(φ): agent i believes φ

Multiple agents:

  • E(φ): everyone knows φ (Everyone knows)
  • C(φ): φ is common knowledge (Common knowledge)

Axioms (system S5):

K1: K_i(φ → ψ) → (K_i(φ) → K_i(ψ)) [distribution law]

K2: K_i(φ) → φ [truthfulness]

K3: K_i(φ) → K_i(K_i(φ)) [positive introspection]

K4: ¬K_i(φ) → K_i(¬K_i(φ)) [negative introspection]

Definition of common knowledge:

```

E(φ) ≝ K₁(φ) ∧ K₂(φ) ∧ ... ∧ Kₙ(φ)

E²(φ) ≝ E(E(φ))

...

C(φ) ≝ E(φ) ∧ E²(φ) ∧ E³(φ) ∧ ...

```

Possible-world semantics:

Epistemic model:

M = (W, {R_i}_{i∈Agents}, V)

  • W: possible worlds
  • R_i: agent i's epistemic accessibility relation (w R_i w' means that in w, i considers w' possible)
  • V: the valuation function

Satisfaction:

M, w ⊨ K_i(φ) iff for all w' such that w R_i w', M, w' ⊨ φ

```

Applications in this book:

  • The formalization of the sociality of knowledge (Chapter 8)
  • The formulation of epistemic communities (Chapter 13)
  • Multi-agent decision-making (Chapter 17)

Epistemic logic in Coq:

```coq

( agents )

Parameter Agent : Type.

( epistemic operators )

Parameter Knows : Agent -> Prop -> Prop.

Notation "'K[' i ']' p" := (Knows i p) (at level 75).

( S5 axioms )

Axiom K_dist : forall (i : Agent) (p q : Prop),

K[i](p -> q) -> (K[i]p -> K[i]q).

Axiom K_truth : forall (i : Agent) (p : Prop),

K[i]p -> p.

Axiom K_pos_intro : forall (i : Agent) (p : Prop),

K[i]p -> K[i](K[i]p).

Axiom K_neg_intro : forall (i : Agent) (p : Prop),

~ K[i]p -> K[i](~ K[i]p).

( common knowledge )

Parameter CommonKnowledge : Prop -> Prop.

Notation "'C' p" := (CommonKnowledge p) (at level 75).

( fixed-point property of common knowledge )

Axiom common_knowledge_fixpoint : forall p,

C p <-> (forall i : Agent, K[i]p) /\ C(C p).

```

§2.2 Mathematical Tools

§2.2.1 Category Theory

Why do we need category theory?

Category theory is "the mathematics of mathematics"; it provides:

  • A unified language for expressing mathematical structures
  • A relation-first perspective (morphisms prior to objects)
  • Rich tools (functors, natural transformations, limits)

This makes category theory naturally suited to formalizing relational ontology.

Basic concepts:

Definition 2.1 (Category):

A category C contains:

  • Obj(C): a collection of objects
  • For any objects A, B, Hom(A, B): the set of morphisms from A to B
  • Composition: ∘: Hom(B, C) × Hom(A, B) → Hom(A, C)
  • Identity morphisms: id_A ∈ Hom(A, A)

Satisfying:

1. Associativity: (h ∘ g) ∘ f = h ∘ (g ∘ f)

2. Unit law: id_B ∘ f = f = f ∘ id_A (for f: A → B)

Examples:

Category Set:

  • Objects: sets
  • Morphisms: functions
  • Composition: function composition
  • Identity: the identity function

Category Grp:

  • Objects: groups
  • Morphisms: group homomorphisms
  • Composition: composition of homomorphisms
  • Identity: the identity homomorphism

Definition 2.2 (Functor):

A functor F: C → D is a mapping between categories:

  • Object mapping: F: Obj(C) → Obj(D)
  • Morphism mapping: F: Hom_C(A, B) → Hom_D(F(A), F(B))

Satisfying:

1. F(id_A) = id_{F(A)}

2. F(g ∘ f) = F(g) ∘ F(f)

Definition 2.3 (Natural Transformation):

A natural transformation η: F ⇒ G (where F, G: C → D are functors) is a family of morphisms:

  • η_A: F(A) → G(A) (for each object A ∈ C)

Satisfying the naturality condition:

  • For any f: A → B, G(f) ∘ η_A = η_B ∘ F(f)

Diagram:

F(A) --η_A--> G(A) | | F(f) G(f) | | v v F(B) --η_B--> G(B)

Definition 2.4 (Limit):

The limit of an object A is an object satisfying the universal property:

  • There exist morphisms π_i: A → A_i (projections)
  • For any object B and morphisms f_i: B → A_i, there exists a unique u: B → A such that f_i = π_i ∘ u

Special limits:

  • Product: A × B
  • Pullback
  • Equalizer

Applications in this book:

  • The formalization of relational ontology (Chapter 4)
  • The theorem of the irreducibility of relations (Theorem 4.7)

Category theory in Coq:

```coq

( definition of a category )

Class Category := {

Obj : Type;

Hom : Obj -> Obj -> Type;

compose : forall {A B C}, Hom B C -> Hom A B -> Hom A C;

id : forall {A}, Hom A A;

( axioms )

compose_assoc : forall {A B C D} (f : Hom A B) (g : Hom B C) (h : Hom C D),

compose h (compose g f) = compose (compose h g) f;

compose_id_left : forall {A B} (f : Hom A B),

compose id f = f;

compose_id_right : forall {A B} (f : Hom A B),

compose f id = f

}.

Notation "g ∘ f" := (compose g f) (at level 40, left associativity).

( definition of a functor )

Class Functor (C D : Category) := {

F_obj : Obj -> Obj;

F_mor : forall {A B}, Hom A B -> Hom (F_obj A) (F_obj B);

( axioms )

F_id : forall {A}, F_mor (@id C A) = @id D (F_obj A);

F_compose : forall {A B C} (f : Hom A B) (g : Hom B C),

F_mor (g ∘ f) = F_mor g ∘ F_mor f

}.

```

§2.2.2 Topology

Why do we need topology?

Topology studies the properties of spaces, in particular:

  • Continuity
  • Connectedness
  • Compactness
  • Dimension

These concepts are crucial for formalizing the "space of possibilities" and "reversibility".

Basic concepts:

Definition 2.5 (Topological space):

A topological space (X, τ) contains:

  • X: a set (a set of points)
  • τ ⊆ ℘(X): a family of open sets

Satisfying:

1. ∅, X ∈ τ

2. Arbitrary unions: {U_i}_{i∈I} ⊆ τ ⇒ ⋃_{i∈I} U_i ∈ τ

3. Finite intersections: U, V ∈ τ ⇒ U ∩ V ∈ τ

Examples:

Euclidean topology:

  • X = ℝⁿ
  • τ = {U ⊆ ℝⁿ | U is a union of open balls}

Discrete topology:

  • τ = ℘(X) (all subsets are open sets)

Trivial topology:

  • τ = {∅, X}

Definition 2.6 (Continuous map):

A map f: X → Y is continuous if:

  • For any open set V ⊆ Y, f⁻¹(V) is an open set in X

Definition 2.7 (Homeomorphism):

A map f: X → Y is a homeomorphism if:

  • f is a bijection
  • Both f and f⁻¹ are continuous

Homeomorphic spaces are "the same" in the topological sense.

Definition 2.8 (Dimension):

The dimension of a topological space has several definitions:

Covering dimension (Lebesgue covering dimension):

```

dim(X) = min{n | every open cover has a refinement in which each point belongs to at most n+1 open sets}

```

Inductive dimension:

```

dim(∅) = -1

dim(X) ≤ n iff for any point x and open neighborhood U, there exists an open neighborhood V such that x ∈ V ⊆ U and dim(∂V) ≤ n-1

```

Properties:

  • dim(ℝⁿ) = n
  • Homeomorphisms preserve dimension

Applications in this book:

  • The topological structure of the space of possibilities (Chapter 23)
  • The topological invariance of RFD (Theorem 23.5)
  • The dimensional characterization of reversibility

Topology in Coq:

```coq

( definition of a topological space )

Class TopologicalSpace (X : Type) := {

Open : (X -> Prop) -> Prop;

( axioms )

open_empty : Open (fun _ => False);

open_full : Open (fun _ => True);

open_union : forall (F : (X -> Prop) -> Prop),

(forall U, F U -> Open U) -> Open (fun x => exists U, F U /\ U x);

open_intersection : forall (U V : X -> Prop),

Open U -> Open V -> Open (fun x => U x /\ V x)

}.

( continuous maps )

Definition continuous {X Y : Type}

`{TopologicalSpace X} `{TopologicalSpace Y}

(f : X -> Y) : Prop :=

forall V : Y -> Prop, Open V -> Open (fun x => V (f x)).

( homeomorphism )

Definition homeomorphism {X Y : Type}

`{TopologicalSpace X} `{TopologicalSpace Y}

(f : X -> Y) : Prop :=

continuous f /\

(exists g : Y -> X, continuous g /\

(forall x, g (f x) = x) /\ (forall y, f (g y) = y)).

```

§2.2.3 Measurement Theory

Why do we need measurement theory?

Measurement theory provides a rigorous foundation for measurement, ensuring that:

  • Measurement is meaningful (representation theorem)
  • Measurement is unique (uniqueness theorem)
  • Measurement can be compared (scale types)

This is crucial for index design.

Basic concepts:

Definition 2.9 (Empirical relational system):

An empirical relational system A = (X, {R_i}_{i∈I}) contains:

  • X: a set of objects
  • {R_i}: a family of relations (such as ≿, ∼, ⊕)

Examples:

  • (X, ≿): a preference relation
  • (X, ≿, ⊕): an additive structure

Definition 2.10 (Numerical relational system):

A numerical relational system N = (ℝ, {S_i}_{i∈I}) contains:

  • ℝ: the set of real numbers
  • {S_i}: numerical relations (such as ≥, =, +)

Definition 2.11 (Representation):

A representation is a homomorphism φ: A → N:

  • It preserves relational structure

Examples:

```

If x ≿ y, then φ(x) ≥ φ(y)

If x ⊕ y ∼ z, then φ(x) + φ(y) = φ(z)

```

Theorem 2.4 (Representation theorem):

Under certain conditions, a representation φ: A → N exists.

Definition 2.12 (Uniqueness):

A representation φ is unique (up to a transformation class T) if:

  • For any representation ψ, there exists t ∈ T such that ψ = t ∘ φ

Scale types:

Scale TypeUniquenessPermitted TransformationsExample
Nominal scaleone-to-one correspondencearbitrary one-to-one correspondenceclassification
Ordinal scalemonotone transformationstrictly increasing functionpreference ordering
Interval scalepositive linear transformationφ' = aφ + b (a > 0)temperature (Celsius/Fahrenheit)
Ratio scalesimilarity transformationφ' = aφ (a > 0)length, mass
Absolute scaleidentity transformationφ' = φcounting

Applications in this book:

  • The measurement-theoretic foundation of UCS (Chapter 22)
  • The representation theorem and uniqueness theorem (Theorem 22.3)
  • The scale-type analysis of indices

Measurement theory in Coq:

```coq

( empirical relational system )

( more relations can be added )

}.

Notation "x ≿ y" := (preference x y) (at level 70).

Definition representation {X : Type} `{EmpiricalRelationalSystem X}

(φ : X -> R) : Prop :=

forall x y, x ≿ y <-> (φ x >= φ y)%R.

( uniqueness (interval scale) )

Definition interval_scale_uniqueness {X : Type}

`{EmpiricalRelationalSystem X}

(φ ψ : X -> R) : Prop :=

exists (a b : R), (a > 0)%R /\ forall x, (ψ x = a φ x + b)%R.

```

§2.2.4 Information Theory

Why do we need information theory?

Information theory provides:

  • A precise definition of entropy
  • A measure of the amount of information
  • A connection between negentropy and information

This is crucial for formalizing the Negentropy Responsibility Principle.

Basic concepts:

Definition 2.13 (Entropy):

The entropy of a discrete random variable X:

```

H(X) = -∑_{x∈X} p(x) log p(x)

```

Properties:

  • H(X) ≥ 0
  • H(X) = 0 iff X is deterministic
  • H(X) is maximal when X is uniformly distributed

Definition 2.14 (Conditional entropy):

The conditional entropy of X given Y:

```

H(X|Y) = ∑_{y∈Y} p(y) H(X|Y=y)

= -∑_{x,y} p(x,y) log p(x|y)

```

Definition 2.15 (Mutual information):

The mutual information of X and Y:

```

I(X;Y) = H(X) - H(X|Y)

= H(Y) - H(Y|X)

= H(X) + H(Y) - H(X,Y)

```

Interpretation: I(X;Y) measures the amount of information shared by X and Y.

Definition 2.16 (Relative entropy / KL divergence):

The relative entropy of a distribution P with respect to Q:

```

D(P||Q) = ∑_x p(x) log(p(x)/q(x))

```

Properties:

  • D(P||Q) ≥ 0
  • D(P||Q) = 0 iff P = Q

Continuous case:

The differential entropy of a continuous random variable X:

```

h(X) = -∫ f(x) log f(x) dx

```

Note: Differential entropy can be negative.

Applications in this book:

  • The formalization of negentropy (Chapter 9)
  • The equivalence of negentropy and information (Theorem 9.8)
  • The information-theoretic formulation of CRV (Chapter 23)

§2.3 Proof Techniques

§2.3.1 Fundamentals of Coq

Introduction to Coq:

Coq is a proof assistant based on the Calculus of Inductive Constructions (CIC).

Core features:

  • Dependent type system
  • Inductive types
  • Tactic language (tactics)
  • Extraction to OCaml/Haskell

Basic workflow:

```coq

( 1. define types and functions )

Inductive nat : Type :=

| O : nat

| S : nat -> nat.

Fixpoint plus (n m : nat) : nat :=

match n with

| O => m

| S n' => S (plus n' m)

end.

( 2. state a theorem )

Theorem plus_O_n : forall n : nat, plus O n = n.

( 3. prove )

Proof.

intros n.

simpl.

reflexivity.

Qed.

( 4. use the theorem )

Theorem plus_n_O : forall n : nat, plus n O = n.

Proof.

induction n as [| n' IHn'].

  • ( n = O )

apply plus_O_n.

  • ( n = S n' )

simpl.

rewrite IHn'.

reflexivity.

Qed.

```

§2.3.2 Fundamentals of Isabelle/HOL

Introduction to Isabelle:

Isabelle is a general-purpose proof assistant,

Isabelle/HOL is its most popular instance (based on higher-order logic).

Core features:

  • Higher-order logic (HOL)
  • Powerful automation tools (Sledgehammer)
  • A rich library (Archive of Formal Proofs)
  • A structured proof language (Isar)

Basic workflow:

```isabelle

theory Example

imports Main

begin

( 1. definition )

fun plus :: "nat ⇒ nat ⇒ nat" where

"plus 0 m = m" |

"plus (Suc n) m = Suc (plus n m)"

( 2. state a theorem )

theorem plus_O_n: "plus 0 n = n"

( 3. proof (automatic) )

by simp

( 4. inductive proof )

theorem plus_n_O: "plus n 0 = n"

proof (induction n)

case 0

show ?case by simp

next

case (Suc n)

then show ?case by simp

qed

( 5. using Sledgehammer )

theorem plus_assoc: "plus (plus n m) p = plus n (plus m p)"

by (induction n) auto

end

```

Isar structured proofs:

```isabelle

theorem plus_comm: "plus n m = plus m n"

proof (induction n)

case 0

have "plus 0 m = m" by simp

also have "... = plus m 0" by (simp add: plus_n_O)

finally show ?case .

next

case (Suc n)

have "plus (Suc n) m = Suc (plus n m)" by simp

also have "... = Suc (plus m n)" using Suc.IH by simp

also have "... = plus m (Suc n)" by simp

finally show ?case .

qed

```

Sledgehammer:

Sledgehammer is Isabelle's automatic proof tool; it:

  • Calls external ATPs (automated theorem provers)
  • Finds relevant lemmas
  • Generates Isabelle proofs

```isabelle

theorem example: "P ∧ Q ⟹ Q ∧ P"

by (sledgehammer)

( Sledgehammer found the proof: by auto )

```

Use in this book:

  • About 30% of the theorems are proved using Isabelle
  • Particularly suited to complex mathematical proofs
  • Code repository: formal-systems/isabelle/

§2.3.3 Fundamentals of Lean 4

Introduction to Lean:

Lean is a modern proof assistant developed by Microsoft Research.

Core features:

  • Dependent type theory
  • A powerful type class system
  • Excellent performance
  • An active community (mathlib)

Basic workflow:

```lean

-- 1. definition

inductive Nat where

| zero : Nat

| succ : Nat → Nat

def plus : Nat → Nat → Nat

| Nat.zero, m => m

| Nat.succ n, m => Nat.succ (plus n m)

-- 2. state a theorem

theorem plus_zero_n (n : Nat) : plus Nat.zero n = n := by

rfl

-- 3. inductive proof

theorem plus_n_zero (n : Nat) : plus n Nat.zero = n := by

induction n with

| zero => rfl

| succ n ih =>

simp [plus]

rw [ih]

-- 4. using tactics

theorem plus_assoc (n m p : Nat) :

plus (plus n m) p = plus n (plus m p) := by

induction n with

| zero => rfl

| succ n ih =>

simp [plus]

rw [ih]

```

Type classes:

```lean

-- define a type class

class Add (α : Type) where

add : α → α → α

-- instance

instance : Add Nat where

add := plus

-- use

def double {α : Type} [Add α] (x : α) : α :=

Add.add x x

eval double 5 -- 10

```

Tactic mode:

```lean

theorem example (p q : Prop) : p ∧ q → q ∧ p := by

intro h

cases h with

| intro hp hq =>

constructor

  • exact hq
  • exact hp

```

Use in this book:

  • About 10% of the theorems are proved using Lean
  • Mainly used to explore novel theorems
  • Code repository: formal-systems/lean/

§2.3.4 Proof Strategies and Techniques

Strategy 1: Induction

Applicable scenario: proving properties of inductive types

Pattern:

```

To prove: ∀n: Nat, P(n)

Base case: prove P(0)

Inductive step: assume P(n), prove P(n+1)

```

Example (Coq):

```coq

Theorem plus_comm : forall n m : nat,

plus n m = plus m n.

Proof.

intros n m.

induction n as [| n' IHn'].

  • ( n = 0 )

simpl.

rewrite plus_n_O.

reflexivity.

  • ( n = S n' )

simpl.

rewrite IHn'.

rewrite plus_n_Sm.

reflexivity.

Qed.

```

Strategy 2: Case analysis

Applicable scenario: proving propositions that involve multiple cases

Pattern:

```

To prove: P(x)

Case 1: assume C1(x), prove P(x)

Case 2: assume C2(x), prove P(x)

...

```

Example (Isabelle):

```isabelle

theorem example: "P x"

proof (cases x)

case Case1

then show ?thesis sorry

next

case Case2

then show ?thesis sorry

qed

```

Strategy 3: Proof by contradiction

Applicable scenario: when a direct proof is difficult

Pattern:

```

To prove: P

Assume: ¬P

Derive a contradiction

Conclusion: P

```

Example (Lean):

```lean

theorem example (p : Prop) : ¬¬p → p := by

intro h

by_contra hnp

exact h hnp

```

Strategy 4: Constructive proof

Applicable scenario: proving existential propositions

Pattern:

```

To prove: ∃x, P(x)

Construct: find a concrete x₀

Verify: prove P(x₀)

```

Example (Coq):

```coq

Theorem exists_example : exists n : nat, n + 5 = 10.

Proof.

exists 5.

reflexivity.

Qed.

```

Strategy 5: Using lemmas

Applicable scenario: a complex proof needs to be decomposed

Pattern:

```

Main theorem: P

Lemma 1: Q

Lemma 2: Q → R

Lemma 3: R → P

Proof: P follows from Lemmas 1, 2, and 3

```

Example (Coq):

```coq

Lemma helper : forall n, n + 0 = n.

Proof. ( ... ) Qed.

Theorem main : forall n m, n + m + 0 = n + m.

Proof.

intros n m.

rewrite helper.

reflexivity.

Qed.

```

Strategy 6: Automation

Applicable scenario: simple or standard proofs

Tools:

  • Coq: `auto`, `omega`, `lia`
  • Isabelle: `auto`, `simp`, `sledgehammer`
  • Lean: `simp`, `omega`, `decide`

Example (Isabelle):

```isabelle

theorem "x + y = y + x"

by (sledgehammer)

( automatically found: by simp )

```

Strategy 7: Rewriting

Applicable scenario: using equational transformations

Pattern:

```

Known: x = y

Goal: P(x)

Rewrite: P(x) = P(y)

Prove: P(y)

```

Example (Coq):

```coq

Theorem example : forall n m,

n = m -> n + 1 = m + 1.

Proof.

intros n m H.

rewrite H.

reflexivity.

Qed.

```

  • Knowledge and belief operators
  • Common knowledge
  • Application: the sociality of knowledge, multi-agent decision-making

1. Category theory

  • Categories, functors, natural transformations
  • Limits and colimits
  • Application: relational ontology

2. Topology

  • Topological spaces, continuous maps
  • Homeomorphisms, dimension
  • Application: the space of possibilities, reversibility

3. Measurement theory

  • Empirical relational systems, representation
  • Representation theorem, uniqueness theorem
  • Scale types
  • Application: index design

4. Information theory
