§26.1　The Problem of Global Consistency

§26.1.1　The Formulation of the Problem

The first six parts of Volume II constructed 27 independent formal systems. These systems have all undergone rigorous consistency tests within their respective domains. But local consistency does not guarantee global consistency.

The problem of global consistency has three levels:

Level One: Cross-system conceptual consistency

Different systems use the same terms (such as "agent," "freedom," "negentropy"), but are the definitions of these terms consistent across the different systems?

For example:

  • "agent" in the New View of Life (the Agent in the SC system)
  • "cognitive agent" in the New View of Cognition (the Cognitive Agent in the PC system)
  • "free agent" in the Recursive Freedom Principle (the Free Agent in the RFP system)

Do these three concepts of "agent" refer to the same kind of entity? If not, what is the relation among them?

Level Two: Cross-system axiomatic consistency

Can the axioms of different systems derive contradictory conclusions?

For example:

  • NRP (the Negentropy Responsibility Principle) requires "maintaining negentropy"
  • REV (the Reversibility Principle) requires "preferring reversible actions"
  • But certain actions that maintain negentropy may be irreversible (such as establishing a complex social institution)

Does this constitute a contradiction?

Level Three: Cross-system inferential consistency

Can a theorem proved in one system conflict with a theorem proved in another system?

For example:

  • The RFP system proves that "maximizing the depth of recursive freedom is a normative requirement"
  • The NRP system proves that "in certain circumstances freedom must be restricted in order to maintain negentropy"

Are these two theorems compatible?

§26.1.3　The Importance of Global Consistency

Why is global consistency so important?

Reason One: The reliability of the theory

If the overall system is inconsistent, then any proposition whatsoever can be derived from it (the principle of explosion). This would rob the entire theory of meaning.

Reason Two: The feasibility of application

The indicator applications and institutional design of Volume III depend on the formal systems of Volume II. If the systems are inconsistent, the applications will lack a reliable foundation.

Reason Three: A response to criticism

A major criticism of the First Edition was "circular co-construction." A proof of global consistency can respond to this criticism: circular co-construction is not equivalent to logical contradiction.

Reason Four: The maturity of the discipline

A mature discipline requires an internally consistent theoretical system. Global consistency is the mark of Interstellar Civilization Studies moving toward maturity.

§26.1.4　Strategies for Testing Global Consistency

Strategy One: The direct proof method

Attempt to prove directly the global consistency of Definition 26.2. This requires:

1. Constructing a joint model of all systems

2. Proving that this model satisfies all axioms

3. Proving that this model contains no contradiction

Difficulty: the joint model of the 27 systems is extremely complex; constructing it directly is all but impossible.

Strategy Two: The reduction proof method

Reduce global consistency to simpler sub-problems:

1. Prove the local consistency of each system (already done in the respective chapters)

2. Prove the interface consistency among systems

3. Prove the acyclicity of the dependency relations

Advantage: modular and manageable.

Strategy Three: Proof by contradiction

Assume the systems are inconsistent, derive a contradiction, and thereby prove consistency.

Difficulty: all possible sources of contradiction must be exhausted.

Strategy Four: The model-theoretic method

Construct a "Universal Model" and prove that this model simultaneously satisfies the axioms of all 27 systems.

Advantage: if successful, it provides a strong proof of consistency.

The strategy adopted in this chapter: we shall mainly use Strategy Two (the reduction proof method), supplemented by Strategy Four (the model-theoretic method).

```python
class DependencyAnalyzer:

def __init__(self, systems):

self.systems = systems

self.graph = self.build_graph()

def build_graph(self):

"""Build the dependency graph"""

graph = {}

for s in self.systems:

graph[s.name] = s.dependencies

return graph

def check_cycles(self):

"""Check for circular dependencies"""

visited = set()

rec_stack = set()

def dfs(node):

visited.add(node)

rec_stack.add(node)

for neighbor in self.graph.get(node, []):

if neighbor not in visited:

if dfs(neighbor):

return True

elif neighbor in rec_stack:

return True

rec_stack.remove(node)

return False

for node in self.graph:

if node not in visited:

if dfs(node):

return True # cycle found

return False # no cycle

def topological_sort(self):

"""Topological sort (determining the construction order)"""

in_degree = {s: 0 for s in self.graph}

for s in self.graph:

for dep in self.graph[s]:

in_degree[dep] += 1

queue = [s for s in in_degree if in_degree[s] == 0]

result = []

while queue:

node = queue.pop(0)

result.append(node)

for neighbor in self.graph.get(node, []):

in_degree[neighbor] -= 1

if in_degree[neighbor] == 0:

queue.append(neighbor)

if len(result) != len(self.graph):

raise Exception("Circular dependency exists")

return result

```

Note 1: On Gödel's incompleteness theorems

This chapter has repeatedly mentioned that "completeness is impossible." This stems from Gödel's First Incompleteness Theorem: any consistent formal system containing enough arithmetic is incomplete. The 27 systems of Volume II clearly contain enough arithmetic (at least in the indicator computations), so they cannot be both consistent and complete. Theorem 26.3 claims that "a justificatory cycle does not affect consistency." This claim may be controversial. Critics may argue that a justificatory cycle weakens the foundational character of the theory. Our response is:

1. The method of reflective equilibrium essentially involves circular justification

2. The justification of scientific theories also involves circularity (theory and observation supporting each other)

3. The key is to distinguish "vicious circles" (definitional cycles) from "virtuous circles" (justificatory cycles)

Note 3: On the ontological commitments of the universal model

The construction of the universal model involves ontological commitments: we commit to the existence of a "universe" containing all entities. This commitment may be controversial:

  • Pluralists may reject the existence of a single universe
  • Anti-realists may reject the reality of the model

Our position is: the universal model is a mathematical construction and does not necessarily commit us to metaphysical realism. It is merely a tool for the consistency proof.

1. It demonstrates the feasibility of formalization

2. It raises the credibility of proofs

  • Use projection operators on a Hilbert space
  • Reference: Birkhoff & von Neumann (1936)

Path Two: Use situation semantics

  • Introduce situations as basic concepts
  • Use partial functions rather than total functions
  • Reference: Barwise & Perry (1983)

Path Three: Use type theory

  • Use dependent types to express the observer-observed relation
  • Use inductive-recursive definitions to handle self-reference
  • Reference: Martin-Löf type theory

  • If PU were proved inconsistent, the PU system would need to be revised
  • But PU's coupling with the other systems is weak, so the impact is controllable
  • Worst case: downgrade PU to a "heuristic framework" rather than a formal system

2. The boundary with probability theory: how are risk and deep uncertainty to be distinguished?

Path One: Use non-monotonic logic

  • Allow the defeasibility of reasoning
  • Use default logic or autoepistemic logic
  • Reference: Reiter (1980)

  • Use membership functions to express uncertainty

```python
report.append(f" cycle {i}: {' -> '.join(cycle + [cycle[0]])}")

else:

report.append("✓ no circular dependencies")

report.append("")

# topological sort

except Exception as e:

report.append("")

# dependency depth

report.append("Dependency-depth analysis:")

max_depth = max(depths.values())

report.append(f" layer {depth}: {', '.join(systems_at_depth)}")

report.append("")

# key nodes (the systems depended on the most)

in_degrees = dict(self.graph.in_degree())

sorted_by_in_degree = sorted(in_degrees.items(),

for system, in_degree in sorted_by_in_degree[:5]:

report.append("")

report.append("=" * 60)
```
