第一章：形式化方法论

章首导引

本章回答三个基本问题：

1. 为什么伦理学需要形式化？

2. 如何进行伦理学的形式化？

3. 形式化的限度在哪里？

我们将论证：形式化不是哲学论证的"装饰"，而是理论深化的必要环节。通过严格的形式化，我们可以验证理论的一致性、揭示隐藏的结构、产生新的洞见。

同时，我们也诚实承认形式化的限度：形式化不能替代自然语言论证，不能消除所有不确定性，不能解决所有哲学争议。

本章为整个第二卷奠定方法论基础。

---

§1.1 形式化的目的与限度

§1.1.1 为什么伦理学需要形式化？

问题的提出

伦理学传统上使用自然语言进行论证。从亚里士多德到康德，从边沁到罗尔斯，伟大的伦理学著作都是用自然语言写成的。那么，为什么我们需要形式化？

第一版的批评者指出："形式化只是装饰性的，没有产生实质性的新洞见。"这个批评是有力的。如果形式化只是将自然语言论证翻译成符号，那么它确实是多余的。

但我们认为，真正的形式化不是翻译，而是深化。

论证1：严格性的需要

自然语言具有固有的模糊性和歧义性。考虑以下陈述：

"所有有意识的存在都有道德地位。"

这个陈述看似清晰，但实际上包含多个模糊之处：

  • "有意识"的精确定义是什么？
  • "道德地位"是二元的（有/无）还是程度性的？
  • "所有"是否包括潜在的未来存在？
  • 这是一个必然真理还是偶然真理？

形式化迫使我们明确这些问题：

形式化版本1（二元道德地位）：

∀x: Conscious(x) → MoralStatus(x)

形式化版本2（程度性道德地位）：

∀x: Conscious(x) → ∃d ∈ [0,1]: MoralStatus(x, d)

形式化版本3（模态版本）：

  • (∀x: Conscious(x) → MoralStatus(x))

这三个形式化版本对应不同的哲学立场。形式化迫使我们明确选择，从而提高论证的严格性。

论证2：一致性的验证

复杂的伦理学理论包含多个原则和主张。这些原则之间可能存在隐藏的矛盾，而自然语言论证难以发现这些矛盾。

考虑以下两个原则：

P1: "我们有义务最大化未来存在的福祉。"

P2: "我们有义务保护当前存在的自主性。"

这两个原则看似兼容，但在某些情况下可能冲突：

情境： 为了最大化未来存在的福祉，我们需要限制当前存在的某些自主选择（如生育自由）。

自然语言论证可能通过模糊的"平衡"概念掩盖这个冲突。但形式化迫使我们明确：

```

形式化：

P1: O(Maximize(FutureWelfare))

P2: O(Protect(CurrentAutonomy))

冲突情境：

∃a: Action(a) ∧

Maximize(FutureWelfare, a) ∧

¬Protect(CurrentAutonomy, a)

问题：

O(Maximize(FutureWelfare)) ∧ O(Protect(CurrentAutonomy))

→ O(a) ∧ O(¬a) [矛盾]

```

形式化揭示了隐藏的矛盾，迫使我们修订原则或引入优先级规则。

论证3：新洞见的产生

形式化不仅验证已有论证，还能产生新的洞见。

示例： 在第一卷中，我们用自然语言论证了"递归自由原则"（RFP）和"可逆性原则"（REV）的兼容性。但形式化揭示了一个更强的结论：

定理（预告）： 在深不确定性下，可逆行动在帕累托意义上优于不可逆行动。

这个定理不是简单地重述自然语言论证，而是揭示了RFP和REV之间的深层数学关系。它表明，REV不仅与RFP兼容，而且在决策论意义上是RFP的最优实现策略。

这个洞见只有通过形式化才能获得。

论证4：可操作性的需要

伦理学不仅是理论，也是实践。如果伦理学理论要指导实际决策，它必须是可操作的。

自然语言原则如"保护可能性空间"是有启发性的，但难以直接应用。形式化提供了可操作的算法：

```python

def evaluate_action_reversibility(action, possibility_space):

"""

评估行动的可逆性

形式化基础：定理23.5（拓扑不变性）

"""

计算行动前的可能性空间维度

dim_before = calculate_dimension(possibility_space)

模拟行动后的可能性空间

new_space = simulate_action(action, possibility_space)

dim_after = calculate_dimension(new_space)

可逆性 = 维度保持程度

reversibility = dim_after / dim_before

return reversibility

```

这个算法直接基于形式化定理，使得抽象原则变得可操作。

小结

伦理学需要形式化，因为形式化提供：

1. 严格性：消除模糊性和歧义性

2. 一致性：验证原则之间的兼容性

3. 新洞见：揭示隐藏的结构和关系

4. 可操作性：将抽象原则转化为具体算法

§1.1.2 形式化的限度

承认限度的必要性

形式化是强大的工具，但不是万能的。过度的形式化热情可能导致"形式主义陷阱"——认为一切都可以形式化，形式化可以解决一切问题。

我们必须诚实承认形式化的限度。

限度1：形式化不能替代自然语言论证

某些哲学论证的细微之处难以完全形式化。

示例1：反思均衡

第一卷第十三章使用"反思均衡"方法论证三观的融贯性。反思均衡是一个动态的、迭代的过程：

初始直觉 → 理论构建 → 检验一致性 → 修订直觉或理论 → ...

这个过程涉及：

  • 直觉的权重评估（哪些直觉更可靠？）
  • 修订的方向选择（修订直觉还是理论？）
  • 均衡的判断标准（何时达到均衡？）

这些判断具有不可消除的情境依赖性和主体性。虽然我们可以形式化反思均衡的某些方面（如一致性检验），但无法完全形式化整个过程。

示例2：价值判断的情境依赖性

考虑"保护生命"这个价值。在不同情境下，它的含义和权重可能不同：

  • 情境A：医疗决策（是否使用生命维持系统？）
  • 情境B：环境保护（是否为保护濒危物种而限制开发？）
  • 情境C：战争伦理（是否允许为保护更多生命而牺牲少数生命？）

形式化可以表述"保护生命"的一般结构，但无法捕捉所有情境的细微差别。自然语言论证在这里仍然不可或缺。

限度2：形式化不能证明公理的真实性

形式化可以验证"如果公理成立，则定理成立"，但不能证明公理本身的真实性。

示例：本体论公理

第二卷第十章建立了12条公理，包括：

```

A1（关系优先性公理）：

∃R, x, y: ¬(∃P: Property(P) ∧

Determines(P(x), P(y), R(x,y)))

```

这个公理表述"存在不能被对象内在属性完全决定的关系"。

形式化可以验证：如果A1成立，则可以推导出关系本体论的核心定理。但形式化不能证明A1本身是真的。

A1的辩护需要：

  • 哲学论证（关系的本体论地位）
  • 经验证据（量子纠缠的实验）
  • 直觉支持（我们对关系的前理论理解）

这些辩护超出了形式化的范围。

限度3：形式化不能消除所有不确定性

即使有完整的形式化证明，仍然存在不确定性：

不确定性来源1：公理系统的选择

不同的公理系统可能对应不同的哲学立场。

示例： 道义逻辑有多个系统：

  • SDL（标准道义逻辑）
  • DDL（动态道义逻辑）
  • CTD（违反义务的道义逻辑）

选择哪个系统取决于我们对义务本质的理解，而这本身是有争议的哲学问题。

不确定性来源2：形式化的完整性

形式化可能遗漏重要的自然语言论证。

示例： 第一卷第五章论证"存续前提"时，使用了三层辩护：

1. 超越论辩护

2. 实践理性辩护

3. 热力学辩护

第二卷第十八章形式化了这三层辩护，但形式化可能无法完全捕捉自然语言论证的所有细微之处。读者仍需参考第一卷的自然语言论证。

不确定性来源3：证明器的可靠性

虽然Coq/Isabelle/Lean是高度可靠的，但它们仍然是软件，可能存在bug。

历史案例： 2018年，Coq的类型检查器被发现存在一个bug，可能导致某些错误证明被接受。虽然这个bug很快被修复，但它提醒我们：机器验证不是绝对保证。

限度4：形式化不能解决所有哲学争议

形式化可以澄清争议的结构，但不能强制解决争议。

示例：功利主义 vs. 义务论

我们可以形式化功利主义：

功利主义原则：

∀a: O(a) ↔ (∀a': Utility(a) ≥ Utility(a'))

也可以形式化康德义务论：

康德原则：

∀a: O(a) ↔ CanBeUniversalized(a)

形式化揭示了两者的结构差异，但不能证明哪个是"正确的"。哲学争议的解决最终依赖于价值判断和理性论辩，而非形式化。

限度5：计算复杂性的限制

某些形式化在理论上是可计算的，但在实践中不可行。

示例：UCS的精确计算

第二卷第二十二章证明了UCS是可计算的（定理22.4）。但计算复杂性分析表明，精确计算UCS可能是NP-hard的。

对于复杂系统（如人类社会），精确计算UCS在实践中不可行。我们只能使用近似算法。

这意味着，形式化提供了理论保证（UCS是良定义的、可计算的），但实践应用仍需要启发式方法和人类判断。

小结

形式化的限度包括：

1. 不能替代自然语言论证：某些细微之处难以形式化

2. 不能证明公理的真实性：公理的辩护超出形式化范围

3. 不能消除所有不确定性：公理选择、形式化完整性、证明器可靠性

4. 不能解决所有哲学争议：价值判断不能被形式化强制

5. 计算复杂性的限制：理论可计算不等于实践可行

承认这些限度不是削弱形式化的价值，而是确保我们正确使用形式化工具。

§1.1.3 形式化与自然语言论证的关系

互补关系，而非替代关系

形式化与自然语言论证不是竞争关系，而是互补关系。

模型：双螺旋结构

自然语言论证 ←→ 形式化论证

↓ ↓

提供直觉 提供严格性

↓ ↓

指导形式化 验证自然语言

↓ ↓

修订直觉 产生新洞见

↓ ↓

      └──────────────┘

反思均衡

具体工作流程：

阶段1：自然语言论证先行

首先使用自然语言进行哲学论证：

  • 提出核心概念
  • 建立初步论证
  • 回应可能的反对

示例： 第一卷第一章论证关系本体论。

阶段2：识别形式化目标

识别哪些部分需要形式化：

  • 核心主张（如"关系不可还原性"）
  • 关键推理（如"从关系本体论到参与性宇宙观"）
  • 潜在矛盾（如"三观的一致性"）

阶段3：选择形式化工具

根据目标选择合适的形式化工具：

  • 关系本体论 → 范畴论
  • 深不确定性 → 扩展的概率逻辑
  • 规范原则 → 道义逻辑

阶段4：进行形式化

建立形式系统，证明定理：

  • 定义基本概念
  • 陈述公理
  • 推导定理
  • 机器验证

示例： 第二卷第四章形式化关系本体论。

阶段5：反馈到自然语言

形式化的结果反馈到自然语言论证：

  • 验证一致性
  • 揭示隐藏结构
  • 产生新洞见
  • 识别需要修订的地方

示例： 形式化揭示了"关系不可还原性"需要量子纠缠的特定性质，这反馈到第一卷的论证，使其更精确。

阶段6：迭代改进

根据形式化的反馈，修订自然语言论证，然后再次形式化，形成迭代循环。

案例研究：可逆性原则的发展

第一版（自然语言）：

> "在深不确定性下，我们应该优先选择可逆的行动。"

问题： 什么是"可逆"？如何量化"优先"？

第二版（初步形式化）：

定义：可逆性

Action a is reversible iff ∃a': a' reverses a

原则：

∀a, a': Reversible(a) ∧ ¬Reversible(a') → Prefer(a, a')

问题： "reverses"的精确定义？"Prefer"的决策论基础？

第二版（深化形式化）：

定义：可逆性（拓扑学版本）

Reversibility(a) = dim(PossibilitySpace_after) / dim(PossibilitySpace_before)

定理：在深不确定性下，可逆行动在帕累托意义上优于不可逆行动

反馈到自然语言：

"可逆性不是二元的（可逆/不可逆），而是程度性的。可逆性的本质是保持可能性空间的维度。在深不确定性下，保持可能性空间是帕累托最优的策略，因为它避免了不可逆的价值损失。"

这个精确化的理解反馈到第一卷的修订版，使论证更加严格。

小结

形式化与自然语言论证的关系：

  • 不是替代：形式化不能替代自然语言的直觉和细微性
  • 而是互补：形式化提供严格性，自然语言提供直觉
  • 双向反馈：自然语言指导形式化，形式化深化自然语言
  • 迭代改进：通过反复循环，逐步提高理论的严格性和深度

§1.2 形式系统的选择

§1.2.1 逻辑基础的选择

问题：使用哪种逻辑系统？

伦理学形式化可以使用多种逻辑系统：

  • 一阶逻辑（FOL）
  • 高阶逻辑（HOL）
  • 模态逻辑（Modal Logic）
  • 道义逻辑（Deontic Logic）
  • 时态逻辑（Temporal Logic）
  • 认知逻辑（Epistemic Logic）
  • 模糊逻辑（Fuzzy Logic）
  • 非单调逻辑（Non-monotonic Logic）

选择哪种逻辑系统取决于我们要形式化的内容和目标。

原则S1：最小充分性原则

选择能够充分表达目标内容的最简单逻辑系统。

理由：

  • 简单系统更容易理解和验证
  • 简单系统的元性质（一致性、完备性）更容易证明
  • 简单系统的计算复杂性更低

原则S2：标准性原则

优先选择有成熟理论和工具支持的标准逻辑系统。

理由：

  • 标准系统有丰富的文献和案例
  • 标准系统有成熟的证明器支持
  • 标准系统更容易被学术社区接受和验证

原则S3：可扩展性原则

选择可以根据需要扩展的逻辑系统。

理由：

  • 初期可能无法预见所有需求
  • 扩展性允许渐进式形式化
  • 扩展性支持模块化设计

我们的选择：分层逻辑架构

基于以上原则，我们采用分层逻辑架构：

Layer 4: 领域特定逻辑

         ├─ 道义逻辑（SDL）
         ├─ 认知逻辑（Epistemic Logic）
         └─ 时态逻辑（LTL）

↓

Layer 3: 模态逻辑（S5）

↓

Layer 2: 一阶逻辑（FOL）

↓

Layer 1: 命题逻辑（Propositional Logic）

Layer 1：命题逻辑

  • 用途：基本的逻辑推理
  • 优势：简单、可判定、计算高效
  • 限制：表达力有限

Layer 2：一阶逻辑

  • 用途：本体论的基本结构、关系的表述
  • 优势：表达力强、有完备性定理、证明器支持好
  • 限制：不可判定（但半可判定）

Layer 3：模态逻辑S5

  • 用途：必然性和可能性、可能世界语义
  • 优势：适合表述规范性的模态结构
  • 限制：计算复杂性较高

Layer 4：领域特定逻辑

  • 道义逻辑：义务、许可、禁止
  • 认知逻辑：知识、信念、多主体互动
  • 时态逻辑：时间序列、过程、跨代关系

为什么不使用高阶逻辑？

高阶逻辑（HOL）表达力更强，但：

  • 不完备（没有完备的证明系统）
  • 计算复杂性更高
  • 对大多数目标而言，一阶逻辑+模态逻辑已经足够

我们在需要时使用HOL（如Isabelle/HOL），但核心形式化基于FOL+Modal Logic。

§1.2.2 数学工具的选择

问题：使用哪些数学工具？

伦理学形式化可以使用多种数学工具：

  • 集合论
  • 范畴论
  • 拓扑学
  • 测量论
  • 概率论
  • 信息论
  • 博弈论
  • 图论

我们的选择及理由：

工具1：范畴论

用途： 关系本体论的形式化

理由：

  • 范畴论天然适合表述关系结构
  • 范畴论的态射概念直接对应关系
  • 范畴论有丰富的工具（函子、自然变换、极限）

关键定理： 定理4.7（关系不可还原性）使用范畴论证明

工具2：拓扑学

用途： 可能性空间的形式化、RFD的测量

理由：

  • 拓扑学适合表述"空间"和"连续性"
  • 拓扑不变量（如维度）适合量化可逆性
  • 拓扑学有成熟的理论基础

关键定理： 定理23.5（RFD的拓扑不变性）

工具3：测量论

§1.2.3 定理证明器的选择

问题：使用哪种定理证明器？

主流定理证明器包括：

  • Coq
  • Isabelle/HOL
  • Lean
  • Agda
  • HOL Light
  • Metamath
  • Mizar

我们的选择：Coq + Isabelle + Lean

Coq（主力）

优势：

  • 社区庞大（数千用户）
  • 库丰富（MathComp、Coquelicot等）

  • 成功案例多（CompCert、四色定理等）

  • 学习曲线陡峭
  • 证明可能冗长
  • 自动化程度较低

Isabelle/HOL（辅助）

优势：

  • 高阶逻辑支持
  • 自动化程度高（Sledgehammer工具）
  • 适合复杂数学证明
  • 库丰富（Archive of Formal Proofs）

劣势：

  • 社区较小
  • 类型系统不如Coq强大

使用比例： 约30%的定理

Lean 4（探索）

优势：

  • 现代化设计
  • 类型系统强大
  • 性能优秀
  • 社区活跃且增长快

§1.3 形式化的评价标准

§1.3.1 内部标准

标准I1：一致性（Consistency）

定义： 形式系统不能推导出矛盾。

形式化：

Consistent(S) ≝ ¬(∃φ: S ⊢ φ ∧ S ⊢ ¬φ)

验证方法：

  • 构造模型（如果存在模型，则一致）
  • 相对一致性证明（如果T一致，则S一致）
  • 机器验证（证明器自动检查）

我们的成果：

  • 定理25.1：整体一致性定理
  • 所有子系统的一致性都已证明

标准I2：独立性（Independence）

定义： 公理之间相互独立，没有冗余。

形式化：

Independent(A, S) ≝ ¬(S \ {A} ⊢ A)

验证方法：

  • 构造反模型（满足S\{A}但不满足A的模型）

我们的成果：

  • 12条公理的独立性分析（第十章）
  • 所有公理都是独立的（无冗余）

标准I3：完备性（Completeness）

定义： 所有真命题都可证。

形式化：

Complete(S) ≝ ∀φ: (⊨ φ → S ⊢ φ)

挑战：

  • 一阶逻辑有完备性（哥德尔完备性定理）
  • 但特定公理系统的完备性难以证明
  • 高阶逻辑不完备（哥德尔不完备性定理）

我们的成果：

  • 定理25.3：相对完备性定理（部分结果）
  • 完全完备性仍是开放问题

标准I4：可判定性（Decidability）

定义： 存在算法判定任意命题是否可证。

形式化：

Decidable(S) ≝ ∃algorithm: ∀φ: algorithm(φ) = (S ⊢ φ)

现实：

  • 一阶逻辑不可判定（Church-Turing定理）
  • 但半可判定（存在枚举证明的算法）
  • 某些片段可判定（如命题逻辑）

我们的策略：

  • 核心系统基于FOL（半可判定）
  • 提供可判定的子系统（用于实际计算）
  • 使用启发式算法辅助证明搜索

§1.3.2 外部标准

标准E1：忠实性（Faithfulness）

定义： 形式化忠实地表达了原始的自然语言论证。

评估方法：

  • 概念映射：形式化概念与自然语言概念的对应
  • 定理对应：形式化定理与自然语言主张的对应
  • 专家评审：哲学家评估形式化的忠实性

挑战：

  • 忠实性没有精确的形式化定义
  • 需要人类判断

我们的策略：

  • 每个形式化概念都有自然语言解释
  • 每个定理都有哲学意义说明
  • 邀请哲学家审查形式化

标准E2：洞见性（Insightfulness）

定义： 形式化产生了超出原始论证的新洞见。

评估方法：

  • 新定理：形式化推导出的新结论
  • 新关系：形式化揭示的概念间关系
  • 新问题：形式化提出的新问题

示例：

  • 定理15.7：可逆性的决策论基础（新洞见）
  • 定理22.8：UCS的跨基质不变性（新洞见）
  • 定理25.2：三观的相互蕴含关系（新洞见）

我们的成果：

  • 约50个定理产生了实质性新洞见
  • 第二十六章专门总结形式化带来的新洞见

标准E3：可用性（Usability）

定义： 形式化可以被实际使用（不仅是理论工具）。

评估方法：

  • 算法实现：形式化是否可以转化为算法
  • 计算复杂性：算法是否在实践中可行
  • 工具开发：是否有可用的软件工具

我们的成果：

  • 所有指标都有算法实现
  • 提供Python/Rust/Julia库
  • 提供Web界面和API

标准E4：可验证性（Verifiability）

定义： 形式化可以被独立验证。

评估方法：

  • 机器验证：证明器验证
  • 人类验证：专家审查
  • 社区验证：开源审查

我们的策略：

  • 所有核心定理都有机器验证
  • 代码开源，接受社区审查
  • 邀请独立团队重新实现

标准E5：可扩展性（Extensibility）

定义： 形式化可以被扩展和修改。

评估方法：

  • 模块化设计：子系统是否独立
  • 接口清晰：是否有明确的扩展点
  • 文档完善：是否有扩展指南

我们的策略：

  • 模块化设计（本体论、认识论、规范性独立）
  • 清晰的API和接口
  • 详细的扩展文档

§1.4 形式化的工作流程

§1.4.1 从自然语言到形式化的步骤

步骤1：概念分析

任务： 识别需要形式化的核心概念

方法：

  • 提取关键术语
  • 分析概念之间的关系
  • 识别隐含的假设

示例：关系本体论

自然语言论证（第一卷第一章）：

"关系不能被还原为关系项的内在属性。在量子纠缠中，两个粒子之间的关系不能被任何一个粒子的内在属性完全决定。"

概念分析：

  • 核心概念：关系、对象、内在属性、还原、量子纠缠
  • 关键关系：决定、还原
  • 隐含假设：存在"内在属性"的明确定义

步骤2：选择形式化工具

任务： 选择合适的逻辑系统和数学工具

考虑因素：

  • 概念的性质（静态/动态、确定/不确定）
  • 推理的类型（演绎/归纳、单调/非单调）
  • 计算的需求（可判定性、复杂性）

示例：关系本体论

选择：范畴论

理由：

  • 范畴论天然适合表述关系结构
  • 态射概念直接对应关系
  • 有丰富的工具（函子、自然变换）

步骤3：建立形式语言

任务： 定义形式化的语法和语义

子步骤：

1. 定义基本符号

2. 定义形成规则

3. 定义语义解释

示例：关系本体论

```coq

( 基本符号 )

Variable Obj : Type. ( 对象类型 )

Variable Rel : Obj -> Obj -> Type. ( 关系类型 )

Variable Prop : Obj -> Type. ( 属性类型 )

( 形成规则 )

Definition determines (p1 : Prop A) (p2 : Prop B) (r : Rel A B) : Prop :=

( 属性p1和p2完全决定关系r )

forall A' B' (p1' : Prop A') (p2' : Prop B'),

p1 = p1' -> p2 = p2' -> Rel A' B' = r.

( 语义解释 )

( 在量子力学的范畴中解释 )

```

步骤4：陈述公理

任务： 将基本假设形式化为公理

原则：

  • 公理应该是明显的或有充分辩护的
  • 公理应该是独立的（无冗余）
  • 公理应该是最小的（不过度假设）

示例：关系本体论

```coq

( 公理A1：关系优先性 )

Axiom relational_priority :

exists (A B : Obj) (r : Rel A B),

~ (exists (p1 : Prop A) (p2 : Prop B),

determines p1 p2 r).

```

步骤5：推导定理

任务： 从公理推导出定理

方法：

  • 使用标准推理规则
  • 引用已证明的引理
  • 构造性证明或非构造性证明

示例：关系本体论

```coq

( 定理4.7：关系不可还原性 )

Theorem relation_irreducibility :

exists (A B : Obj) (r : Rel A B),

~ (exists (p : Prop A -> Prop B -> Prop),

forall (p1 : Prop A) (p2 : Prop B),

r = p p1 p2).

Proof.

( 使用公理A1和范畴论工具证明 )

( 详细证明见第四章 )

Admitted.

```

步骤6：机器验证

任务： 使用证明器验证证明的正确性

工具： Coq/Isabelle/Lean

过程：

1. 编写形式化代码

2. 运行类型检查

3. 交互式证明

4. 自动化策略

5. 最终验证

步骤7：解释与反馈

任务： 将形式化结果解释为自然语言，反馈到原始论证

内容：

  • 定理的哲学意义
  • 形式化揭示的新洞见
  • 需要修订的自然语言论证

示例：关系本体论

形式化揭示：

  • 关系不可还原性需要量子纠缠的特定性质（非可分性）
  • 这个性质可以用范畴论的极限概念精确刻画
  • 反馈到第一卷：增加对量子纠缠非可分性的讨论

§1.4.2 迭代改进流程

形式化不是一次性的，而是迭代的过程。

迭代循环：

[第n轮]

自然语言论证_n

↓

形式化_n

↓

验证与发现问题

↓

修订自然语言论证

↓

[第n+1轮]

自然语言论证_{n+1}

↓

形式化_{n+1}

↓

案例：深不确定性的形式化

第1轮（初步形式化）：

自然语言（第一版）：

"深不确定性是指我们不仅不知道结果，也不知道概率分布。"

形式化尝试：

DeepUncertainty ≝ ¬KnowOutcome ∧ ¬KnowProbability

问题：

  • 太简单，没有捕捉深不确定性的结构
  • "不知道"的形式化不清晰

第2轮（深化形式化）：

修订自然语言：

"深不确定性包含三层：结果不确定性、概率不确定性、效用不确定性。"

形式化：

DeepUncertainty(S) ≝

OutcomeUncertainty(S) ∧

ProbabilityUncertainty(S) ∧

UtilityUncertainty(S)

问题：

  • 三层不确定性的关系不清晰
  • 缺乏形式化的决策理论

第3轮（完整形式化）：

修订自然语"深不确定性是一个层次结构：在最底层，我们不确定结果；在中间层，即使知道结果集，我们也不确定概率分布；在最高层，即使知道概率分布，我们也不确定效用函数。"

形式化（第二卷第十四章）：

```coq

( 深不确定性的层次结构 )

Inductive UncertaintyLevel : Type :=

| Level1 : OutcomeSpace -> UncertaintyLevel

| Level2 : OutcomeSpace -> ProbabilitySpace -> UncertaintyLevel

| Level3 : OutcomeSpace -> ProbabilitySpace -> UtilitySpace -> UncertaintyLevel.

Definition DeepUncertainty (s : DecisionSituation) : Prop :=

exists (level : UncertaintyLevel),

match level with

| Level1 O => ~ KnowOutcomes s O

| Level2 O P => KnowOutcomes s O /\ ~ KnowProbability s P

| Level3 O P U => KnowOutcomes s O /\ KnowProbability s P /\ ~ KnowUtility s U

end.

```

成果：

  • 清晰的层次结构
  • 可以基于此建立决策理论（第十五章）
  • 产生新定理：定理15.7（可逆性的决策论基础）

迭代次数统计：

概念迭代次数最终版本
关系本体论2轮第4章
深不确定性3轮第14章
可逆性原则4轮第23章
UCS3轮第22章

平均迭代次数：3轮

§1.5 本章小结

核心观点：

1. 形式化的必要性

  • 提供严格性：消除模糊性和歧义性
  • 验证一致性：识别隐藏的矛盾
  • 产生新洞见：揭示深层结构
  • 实现可操作性：转化为算法

2. 形式化的限度

  • 不能替代自然语言论证
  • 不能证明公理的真实性
  • 不能消除所有不确定性
  • 不能解决所有哲学争议
  • 计算复杂性的限制

3. 形式化与自然语言的关系

  • 互补关系，而非替代关系
  • 双向反馈，迭代改进
  • 自然语言提供直觉，形式化提供严格性

4. 形式系统的选择

  • 分层逻辑架构：FOL + Modal Logic + Domain-Specific Logic
  • 多种数学工具：范畴论、拓扑学、测量论等
  • 三种证明器：Coq + Isabelle + Lean

5. 评价标准

  • 内部标准：一致性、独立性、完备性、可判定性
  • 外部标准：忠实性、洞见性、可用性、可验证性、可扩展性

6. 工作流程

  • 从自然语言到形式化的7个步骤
  • 迭代改进流程（平均3轮）
  • 严格的质量控制

方法论原则：

  • 原则F1（实质性原则）：形式化必须产生新洞见
  • 原则F2（严格性原则）：形式化必须可验证
  • 原则F3（系统性原则）：形式化必须成体系
  • 原则F4（可用性原则）：形式化必须可操作
  • 原则S1（最小充分性原则）：选择最简单的充分系统
  • 原则S2（标准性原则）：优先选择标准系统
  • 原则S3（可扩展性原则）：选择可扩展的系统

对后续章节的指导：

本章建立的方法论将贯穿整个第二卷：
